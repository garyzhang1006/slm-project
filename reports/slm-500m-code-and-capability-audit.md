# 500M code and answer-quality audit

The checkpoint contains 499,524,075 trainable parameters, but it does not reliably answer ordinary English questions. Review of twelve unseen prompts found zero correct answers against the recorded rubrics. The familiar greeting control passed. These are small diagnostic probes, not a statistically representative benchmark or independent human evaluation.

## Code fixes

- Inference memory-maps ZIP checkpoints and excludes optimizer state from its returned payload. Legacy non-ZIP files still load eagerly; resume retains complete training state.
- The launcher limits its PyTorch import probe to 30 seconds and reports failures. This does not establish the cause of earlier Mac hangs or guarantee subsequent model loading.
- Configurations and tokenizers require the supported 259-token byte vocabulary. Unsupported output token IDs can no longer be enabled by enlarging vocabulary size alone.
- Generation rejects nonfinite temperatures before calling the model.
- Data audits detect normalized duplicate prompts across splits even when record IDs differ.
- Repetition evidence redacts original text before displaying it, preserving case-sensitive secret recognition.
- Python extraction ignores code fences tagged with other languages.
- Checkpoint comparisons release each model before loading the next.
- Curriculum wording no longer requests two sentences when its supplied answer contains one.

No model weights were retrained or replaced. The suite passing does not prove absence of all bugs, and these fixes do not make the failed answers correct. Broad language pretraining followed by instruction tuning and fresh held-out evaluation is still needed before presenting this custom checkpoint as a useful question-answering assistant.
